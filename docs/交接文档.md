## 四、流程与命令

```bash
# 依赖（容器重建后需要重装；ffmpeg、gh 已有）
pip install faster-whisper pillow numpy

# 1. 分析一个剧集（每个视频完成即推送）
python3 tools/analyze_video.py --series "Laser Maintenance Group Safety" --push

# 2. 编写（每个视频由一个子任务按 writer_brief 完成）后校验 + 推送
python3 tools/cartoon/build_project.py --only "project/<剧集>/<视频>"
python3 tools/publish.py "<剧集>" "<视频>"

# 3. 重复视频
python3 tools/copy_duplicates.py && python3 tools/publish.py "<剧集>" --all

# 4. 生成与拼接（需要用户本地 ComfyUI + MiniMax H3 模型，本容器没有 GPU，未执行过）
COMFY_URL=http://127.0.0.1:8188 python3 tools/cartoon/generate.py "project/<剧集>/<视频>"
python3 tools/cartoon/assemble.py "project/<剧集>/<视频>"
```

### 剧本规则要点（build_project.py 强制校验）

- `SHOTS` 每项 `(知识点编号, 中文画面, 英文画面, 旁白[, 顶部文字[, [图示文字...]]])`；每镜 5 秒；旁白 ≤20 字（不含标点）；全片 2–15 分钟（24–180 镜）。
- 知识点：原片 `K1…`（全部覆盖），审查补充 `S1…`；特殊段 `开场` `情景` `小结` `结尾`（结尾唯一且在最后）。
- 英文画面不能有中文；固定角色只用 `panda mascot`（欣欣，出现即熊猫出镜说话）、`female graduate student`（小研）、`older man`（老周）、`young male student`（阿杰）、`safety administrator`（王老师）、`facility engineer`（老李）、`security officer`（保卫处值班员）。
- 画面不出文字；需要汉字用图示文字（≤5 个，每个 ≤8 字）；错误做法用图标打叉，不展示危险操作细节、配方、参数。
- `META["avoid"]` 列原片的机构、品牌、型号、人名、频道名；默认已含 MIT、CDC、ACS、iGEM、Thermo 等，命中即报错。

## 五、经验与注意事项（重要）

**环境**
- 仓库是私有的，Release 附件不能直接 curl；`gh release download` 走 GraphQL 被代理拒绝。用 REST：`gh api -H "Accept: application/octet-stream" repos/hanrongwx-max/videoyoutubo/releases/assets/<asset_id>`（`analyze_video.py` 已封装）。
- faster-whisper 自带的 av 解码报错（`metadata_errors`），所以用 ffmpeg 解出 16k PCM 再喂给模型（已封装）。CPU 4 核：small.en 约 6–10 倍实时，一小时的讲座约 10 分钟。
- ffmpeg 的 `select=scene` 对部分 AV1 文件一帧都不出 → 改用自写帧差法（硬切 + 1 秒窗口检测叠化）；长镜头（>30 s）每 15 秒补一帧，拼图仍完整。
- 印地语视频（Electrical Safety、ACS Hazard Communication 部分）：自动用多语种 small 模型 `task=translate` 译成英文，质量一般，编写时以画面幻灯片为主，并在文档中注明。
- **不要用 `pkill -f <含关键字>`**：会匹配到执行它的 shell 自己（退出码 144）。用 `ps | grep` 找 PID 后 `kill`。
- 后台长任务用 `nohup bash 脚本文件 &`（脚本文件名不含要 pgrep 的关键字）。
- 磁盘：分析完默认删除原视频；`work/` 素材约 2MB/视频（主要是拼图）。

**并行编写**
- 用 Agent 子任务并行（一次 3–6 个，每个 1–7 个视频，按时长分配；>30 分钟的讲座单独一个）。派单文本 = “读 `docs/handoff/writer_brief.md`（+ 对应 series_note）并执行，剧集 = …，视频 = 以 0X_ 开头的……”，并写明同剧集其他视频由谁负责、已有哪些 S 点不要重复。
- 子任务共享临时目录，提醒其临时文件用唯一文件名；`build_project.py` 会生成 `__pycache__`，提交前删除（publish.py 已处理）。
- `build_project.py` 不带 `--only` 时会重建全部制作包和 INDEX，多个子任务同时跑可能互相覆盖 `project/INDEX.md`，无害，最后统一重建一次即可。

**内容审查经验（各子任务已反复遇到）**
- 美国制度一律本土化：OSHA/CFR/NFPA/NRC/EPA/RCRA/911 → 国内法规、高校三级管理、119/120 + 报告实验室负责人→学院→保卫处；美国数值（ft、psi、gallon、fpm、mrem、PEL、15 分钟冲洗等）不写进剧本，写“以现行文本和本校规定为准”。
- 不编造条款号和数值；不确定的法规写“以现行文本为准”。需人工核实的：HJ 1188-2021《核医学辐射防护与安全要求》是否存在、《危险化学品安全法》施行情况、《基因工程安全管理办法》是否仍有效。
- 常见原片问题：示范者不戴护目镜/手套、液体倒进下水道、旧版标识（NFPA 菱形）、把灭火类别按美国 A/B/C/D、国际病原危害分级与国内（第一类最危险）方向相反。
- 讲座类视频的幻灯片常有数值错误（剂量、半值层、单位），在内容文档里核算并标出，剧本不用这些数值。
- 版权：只保留知识点（事实和方法），旁白、情节、画面全部重写；真实人物（如主持人访谈）不出现在卡通里，改成熊猫主持；真实事故的地名、遇难者姓名、新闻截图不用。

**剧集名与内容不符（已在各审查报告中说明）**
- `RSO Training Series` 02、05：RSO = Recognized Student Organization（学生社团政策），不是辐射安全员；按非安全视频处理，补社团活动安全 S 点。
- `ACS Hazard Communication & Safety`：大多是印度 HSE 安全员面试问答（部分印地语）。
- `Fire Safety & Extinguisher Training`：其实是商业实验室安全培训片（防污染、人机工效、通风柜、SDS、易燃易爆、甲醛、洗眼器、气瓶、入门）。
- `Acids, Bases & Solvents Safety`：12 个模块的实验室安全管理课（NotebookLM 生成的幻灯片视频，倒序编号）。
- `Fume Hood & Cabinet Protocols`：化学实验基本操作演示（玻璃仪器、过滤、萃取、蒸馏、重结晶、滴定、色谱、原电池、阿司匹林合成）。
- `General Lab Safety Practices` 08：合成生物学建模讲座（52 分钟）。
- `Industrial Gas & Cryogenic Equipment`：经销商的产品宣传短片，剧本只讲通用设备类别，不出现品牌。

**重复视频**：13 组（按 YouTube 链接），9 个已复制。`Laser Maintenance Group Safety` 内部有 4 组重复（05/11、06/10、07/13、08/14）：写完前一个后跑 `tools/copy_duplicates.py`。

## 六、接手步骤

1. 取代码：`git fetch origin claude/youthful-johnson-wuasio && git checkout claude/youthful-johnson-wuasio && git pull`；`pip install faster-whisper pillow numpy`。
2. 检查未完成：`python3 tools/cartoon/build_project.py`，有“问题”的视频或只有 `src.py` 没有 `审查报告.md` / 内容文档的，按 writer_brief 补完。Electrical Safety 07 起尚未编写。
3. 重启分析队列（后台，每个视频完成自动推送；已编写的视频自动跳过）：
   ```bash
   cat > /tmp/queue.sh <<'EOF'
   cd "$(git rev-parse --show-toplevel)"
   for s in "Electrical Safety Series" "Laser Maintenance Group Safety" "Basic Electrical Engineering Lab" "MIT Digital Lab Techniques Manual" "Cleanroom & Equipment Safety" "Laboratory Ergonomics & RSI" "BIORISK MANAGEMENT" "Microbiology Biosafety"; do
     python3 tools/analyze_video.py --series "$s" --push
   done
   EOF
   nohup bash /tmp/queue.sh > /tmp/queue.log 2>&1 &
   ```
4. 随着分析完成，按剧集派编写子任务（见第五节“并行编写”）。各剩余剧集的提示：
   - **Electrical Safety 07–25**：用 `series_note_elec.md`（印地语、HSE 学习指南、工业电气）。
   - **Laser Maintenance Group Safety**：激光加工设备维护安全，参照 `series_note_ph.md` 的激光 S 点；先写不重复的，再跑 `copy_duplicates.py`。
   - **Basic Electrical Engineering Lab**：电工实验课操作，参照 `series_note_tech.md` 的写法 + `series_note_elec.md` 的法规。
   - **MIT Digital Lab Techniques Manual**（每集约 1 小时多的技术手册，14 已复制自 General Lab Safety Practices 02）：用 `series_note_tech.md`；每集压缩到 ≤15 分钟、20–35 个 K 点。
   - **Cleanroom & Equipment Safety**、**Laboratory Ergonomics & RSI**：先看分析结果判断实际内容，再写 series note。
   - **BIORISK MANAGEMENT**、**Microbiology Biosafety**（共 106 个）：生物安全，法规用《生物安全法》《病原微生物实验室生物安全管理条例》、GB 19489-2008、WS 233-2017、《人间传染的病原微生物目录》（注意国内分类方向）；可参考已完成的 `project/CDC Laboratory Safety Series/` 09–16。
5. 每个视频写完立即 `python3 tools/publish.py "<剧集>" "<视频>"`；每个剧集完成后 `python3 tools/cartoon/build_project.py` 重建 INDEX 并推送。
