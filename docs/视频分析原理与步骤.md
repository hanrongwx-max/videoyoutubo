# 视频内容分析的步骤与原理

视频内容分析分两个阶段：

1. **自动分析**：由脚本 `tools/analyze_video.py` 在本机运行，不消耗额度。
2. **编写**：由 Claude 编写子任务看自动分析的结果写文档和剧本，消耗额度。

规则细节见 `docs/卡通改编规范.md`，编写任务说明见 `docs/handoff/writer_brief.md`，接手说明见 `docs/交接文档.md`。

## 第一阶段：自动分析（本机运行，不消耗额度）

每个视频依次经过以下 7 步。输出在 `work/<剧集>/<视频名称>/`。

### 1. 下载附件

- 仓库是私有的，网页链接下载会返回 401，所以通过 GitHub REST API 按附件 ID 取文件：
  `gh api -H "Accept: application/octet-stream" repos/hanrongwx-max/videoyoutubo/releases/assets/<asset_id>`
- 附件 ID、剧集名、视频名称对照表在 `tools/assets.tsv`，由 `tools/manifest.py` 从 Release 列表生成。

### 2. 读取视频信息

用 `ffprobe` 读时长、分辨率、音视频编码，写入 `info.json`。

### 3. 语音转写

使用 faster-whisper（OpenAI Whisper 的 CTranslate2 加速版，CPU int8 量化）。

- 用 ffmpeg 把音轨解成 16kHz 单声道 PCM，再交给模型。faster-whisper 自带的解码库在本环境会报错，所以改由 ffmpeg 负责解码。
- **自动识别语种**：先用多语种 small 模型听视频中部约 30 秒（避开片头音乐）。
  - 英语：用英语专用的 small.en 模型转写，准确率更高。
  - 其他语种（如印地语）：用 small 模型的翻译模式直接输出英文。机器翻译质量一般，编写时以画面上的幻灯片文字为准。
- 开启语音活动检测（VAD），跳过静音和纯音乐段，减少模型“幻听”出不存在的句子。
- 输出带时间戳的分段，保存为 `transcript.json`（记录语种、模型和转写/翻译方式）和 `transcript.srt`。

### 4. 镜头切分（自写的帧差法）

ffmpeg 自带的场景检测（`select=scene`）对部分 AV1 编码的视频一帧都不输出，所以改用自己的算法：

- 每秒抽 5 帧，缩成 64×36 的灰度小图。
- **硬切**：相邻两帧的平均像素差超过阈值，判为切镜。
- **叠化/淡入淡出**：当前帧与 1 秒前的帧差别大，且是前后 1 秒内的峰值，判为一次转场。
- 短于 2 秒的片段并入前一镜，避免闪烁画面被切得过碎。

输出每个镜头的起止时间，保存为 `shots.json`。

### 5. 抽关键帧

- 每个镜头在中点取一帧，宽 640 像素。
- 超过 30 秒的长镜头（讲座、单机位演示）每 15 秒补一帧，保证画面内容变化不会漏掉。

单帧存在 `frames/`，不入库，可以随时重建。

### 6. 拼关键帧图

每张图 4×3 共 12 格，每格标“镜头号 + 时间”，保存为 `sheet_NN.jpg`。编写者用看图的方式，一次能看到一段时间内的全部画面。

### 7. 生成分析底稿

按每个转写分段的中点时间归到对应镜头，得到“镜头 | 时间 | 关键帧 | 该镜头内的讲解”对照表，保存为 `analysis.md`。

### 完成后

- 删除原视频以节省磁盘（`--keep-video` 可保留）。原视频和单帧不入库。
- 用 `tools/publish.py` 把 `work/<剧集>/<视频>/` 提交并推送到 GitHub（`--push` 参数）。该脚本用文件锁避免多个进程同时操作 git，推送失败会重试，遇到远端有新提交会先 rebase。
- 分析中途的半成品先写在 `work/.inprogress/`（不入库），完成后才移入正式目录。
- 已有剧本（`project/…/src.py`）或已有 `analysis.md` 的视频会自动跳过。

### 命令

```bash
pip install faster-whisper pillow numpy          # 另需 ffmpeg 和已登录的 gh
python3 tools/analyze_video.py --series "<剧集>" --push            # 整个剧集
python3 tools/analyze_video.py --series "<剧集>" --only 01 02 --push  # 指定序号
```

## 第二阶段：编写（Claude 子任务，消耗额度）

每个视频由子任务按 `docs/handoff/writer_brief.md` 和对应剧集的说明（`docs/handoff/series_note_*.md`）完成：

1. **看懂视频**
   - 逐张查看关键帧拼图，识别画面内容和屏幕文字：字幕、幻灯片、标签、警示牌。
   - 结合转写文本理解讲解内容，并纠正识别错误（例如把 “salt in crustaceans” 改正为 “salt incrustations”）。
2. **写视频内容文档 `course/<剧集>/<视频>.md`**
   - 基本信息、内容概要。
   - 知识点 K1…，每条注明时间点。
   - 逐段讲解，附关键原话摘录。
   - 画面文字（字符）。
   - 逐镜头说明表。
   - 原片的错误和不足。
3. **审查（`project/<剧集>/<视频>/审查报告.md`）**
   - 逐条对照国内法规、标准和高校安全教育要求，结论分为符合 / 需修改 / 需本土化。
   - 检查完整性，缺失的知识点作为补充知识点 S1… 补入。
   - 列出不适宜的内容和处理办法。
   - 版权处理：只保留知识点，重新创作旁白、情节和画面，原片的机构、品牌、人名列入回避清单（`META["avoid"]`）。
4. **写卡通剧本 `src.py`**：每镜 5 秒、旁白不超过 20 字，使用固定角色（熊猫欣欣主持，与 ppplus107 一致），英文画面提示词给 MiniMax H3 用。
5. **校验与生成**：运行 `tools/cartoon/build_project.py` 自动检查规则（字数、知识点覆盖、时长、回避词等），通过后生成制作包（分镜、字幕、提示词 `prompts.json`、ComfyUI 工作流）。
6. **推送**：每完成一个视频立即用 `tools/publish.py` 推送到 GitHub。

## 局限

- **语音转写**：small 模型在口音重、术语多或背景噪声大时会出错，非英语视频经机器翻译误差更大。所以编写时要求以画面文字为准，并在文档中注明转写错误。
- **镜头切分**：同一场景内的推拉镜头可能不会被切开，由长镜头每 15 秒补帧弥补。
- **画面理解**：靠编写子任务看拼图完成，没有单独的文字识别（OCR）步骤，看不清的文字在文档中标为“不可辨认”。
